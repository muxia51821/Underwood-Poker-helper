# Poker 网页版重设计实施路线图

本文件规定新版的实施顺序、复用决策、数据保护和每批验收门槛。页面与流程以 [新版蓝图](poker-redesign-blueprint.md) 为准；GTO Wizard 的观察结果与可移植性以 [研究记录](gto-wizard-observation.md) 为准。研究证据不足的功能不能因进入路线图就被视为已经验证。

2026-10-16 实施进度：备份与收尾切片后，已实现类别级翻前范围的本地查看、编辑、对照和文件交换，见[范围工作区验证](range-workspace-validation.md)。这不表示可靠答案、组合级训练、版本化训练快照或缓存升级批次已经完成。

后续范围工作区、答案数据与开源工具的建设建议见[产品方向研究](poker-product-direction.md)，具体项目核查见[工具研究](poker-tooling-research.md)。这两份补充研究不改变本文件的恢复与离线验收要求。

本文件保留首次研究时的规划与源码快照；后续已实施行为以 `CONTEXT.md`、[架构说明](ARCHITECTURE.md)和[用户验收清单](acceptance.md)为准。备份与收尾批次的交付证据见[验证记录](backup-closeout-validation.md)。

本阶段只交付研究与规划文档，不改应用代码、真实数据、依赖、Git 历史或生产环境。下列批次是后续实施任务，不是已实现功能。个人 Cash 主线沿用 9max／200bb，次线为 6max／100bb；历史手牌的实际条件与目标档案分别显示。

后续实施以木下完成真实任务的体验为依据：快记能找回、复盘能理解、练习能对应问题、进展能回看。第三方研究已经收束，免费额度、对方跨刷新历史保存和内部策略接口不进入任务列表，也不阻塞任何实施批次。数据恢复、离线与学习记录测试针对本项目自身的实际功能安排。

### 恢复规则

1. R0 先建立无写入的备份读取与校验，生成待导入计划、分类计数、冲突及无法识别项；校验失败不改现有库。
2. 备份包含格式版本、应用来源版本、创建时间、原业务对象与独立学习状态。未知业务字段原样保留；未知本地键只进入恢复快照，不自动执行或激活。迁移 gate、缓存和业务数据分别处理。
3. 同一来源重复导入不增加重复记录；保留所有已有主键、GG 标识和关联。缺失／非法主键先列为待处理，不能静默丢弃或生成随机主键破坏关系。相同 ID 的不同内容保留本地，并列出冲突供用户选择。
4. 写入前保存恢复快照；全部写入完成并读回校验后才报告成功。失败时保留旧数据和失败报告，支持按同一计划重试；部分完成不能显示为完整恢复。业务模块通过公开 Repo／持久化接口工作，不依赖 `_cache` 等内部字段。
5. 初期保留现有库与键名，不为换界面立即更换 DB。确需新增持久化对象时用增量 store／字段，与旧对象分离。仅成功读回后标记迁移完成，不删除旧源；回滚验证完之前保留原始快照。
6. Netlify、GitHub Pages、不同域名和旧 `file://` 数据不能假设共用存储；跨来源、跨设备一律由用户主动导出／导入。新站无法读取旧来源时给出回旧入口导出的步骤，不声称数据为空即已丢失。

跨 IndexedDB 集合与 localStorage 的恢复不能假定存在一个总事务。若中途失败，报告已完成与未完成项，保留恢复前快照并允许幂等重试或主动还原；不把“已请求写入”或“部分写入成功”显示为完整成功。实现先采用这条可验证路径，不为首版引入通用迁移引擎。

## 3. 推荐技术与离线行为

保留已锁定的 Vite 与 Vanilla ES modules。新版采用多文件应用壳、按页面加载的本地模块和统一设计变量；先用 CSS 与现有组件能力完成响应式界面。默认不增加框架、后端、账户、外部 CDN 或运行时依赖。实现中若出现无法用当前能力合理解决的需要，再提出有具体用途的依赖变更。

路由采用 hash，兼容 GitHub Pages 的子路径与直接刷新；从现有 `Navigation` 的 Hand、Session、Strategy、Opponent、LearningTarget 意图过渡，链接只携带本地 ID 与筛选上下文，不将手牌正文放入地址。计时服务跨路由常驻，页面切换不得反复初始化计时或重复订阅事件。

R4 新增 `DrillPreset`（保存专项）、`PracticeSession`（一次练习）和 `PracticeAttempt`（一次作答），与真实牌局的 `SessionRepo`／`HandRepo` 分开。专项保存 `learningQuestion`、题型、适用的练习跨度和场景筛选；练习固定本次题目、来源与条件版本并保存可选的复盘短记；作答保存原回答、该题实际条件、反馈及评分版本。最小公共元数据为 `type`、`scope`、`sourceRevision`、`conditions`，并保留可选的来源手牌／策略 ID。历史资料不具备的条件保持未知，不能用目标档案回填为已匹配；所有新增对象必须同批进入备份、导入和失败恢复。详细页面行为见蓝图；可移植能力的数据要求见[研究记录](gto-wizard-observation.md#可移植能力与数据边界)。

未来 R1 移除新版构建路径中的 `vite-plugin-singlefile`，输出带内容 hash 的 JS／CSS 和本地资源清单；保留 `CONSTANTS.VERSION` 为版本唯一来源。同步调整产物检查、CSP 和现有单文件假设，并把已批准的网页优先方向写入治理／架构／工作流文档。此时才取消新版的 `file://` 双击验收；旧文件继续作为独立旧版使用，数据通过手动备份转移。

| 场景 | 必须表现 |
| --- | --- |
| 首次访问 | 需要网络下载应用；页面可先使用，但缓存完成前不显示“可离线使用”。不承诺从未访问过的页面可断网启动。 |
| 缓存完成 | 预缓存应用壳、核心页面模块、策略／概念资料与必要图标；读回确认后显示离线可用。不得把“页面加载成功”等同于缓存完成。 |
| 断网 | 已缓存入口可启动；计时、赔率、快记、已存手牌、导入、复盘、已缓存学习和训练保持可用。外部来源链接明确需要联网，反馈不能依赖 Wizard 接口。 |
| 发现新版 | 新 SW 下载完整资源集后等待；在有活动计时、未保存编辑或写入任务时不强制切换。用户主动更新前保留现有资源集。 |
| 应用更新 | 先完成写入和必要备份，再切换整套资源；避免旧 HTML 与新模块混用。多标签有未完成工作时推迟激活，展示需关闭／保存的状态。 |
| 下载中断或缓存损坏 | 未完整安装的版本不激活；保留最后一个可用应用缓存。联网可重建应用缓存，不清理业务存储；没有可用缓存时明确说明需要联网恢复。 |
| 浏览器清理／配额不足 | 说明缓存与业务数据的实际状态；持久化失败不得报“保存成功”。文件备份是用户可掌握的恢复渠道，不能承诺浏览器存储永不被清理。 |

当前 SW 在 install 中 `skipWaiting()`、activate 中清理旧缓存并 `clients.claim()`；不能直接照搬到多文件新版。R1 以受控更新状态机替代，并验证同一版本资源集完整性。通知与后台提醒继续受浏览器权限和系统调度限制，不承诺关闭应用后可靠报时。

各批按 [开发工作流](workflow.md) 选择与影响范围对应的检查，发布前运行完整基线。R1 更新构建契约之后，`npm run check` 应验证多文件网页产物，不能简单删除原单文件断言而不建立替代保护。数据验证使用合成手牌和合成存储；真实数据由木下在备份后完成最终用户验收。

R4 按本项目的学习任务验收：固定与混合筹码专项分别保存和统计；动作来自各题合法动作；反馈时机与题型分开；切换题目保留已输入的选择和理由，只有会丢失输入时才提示确认。以“从一个问题进入练习，回看自身及对手范围 / 假设，比较相似场景并形成理解”为主要使用链；允许直接自由练习和可选短记，不强迫填写流程表。样本不足时说明缺口，不虚构对手范围或教学解释；地址与可访问内容不能提前泄漏盲测答案。

### 首批开发规格：R0

R0 处理当前重设计会直接遇到的备份缺口，不建设通用同步平台。结果应让用户能主动下载完整本地备份，并在导入前看清内容及冲突，为换壳保留可靠恢复路径。

以下为后续允许触及的建议范围，不是本阶段改动清单：

| 范围 | 建议改动 | 保留的边界 |
| --- | --- | --- |
| `src/store/backup.js`（建议新增） | 集中定义备份格式、独立键清单、解析校验与无写入合并计划 | 不读取浏览器账号、认证记录或其他应用数据；不为重设计复制一套 Repo。 |
| `src/store/store.js`、`src/store/storage.js` | 经公开接口收集集合与原始独立键；可等待写入并读回核对；暴露失败项 | 保留库名、ID、既有字段和手牌事实；不借此改造统计或解析算法。 |
| `src/modules/dataSync.js`、现有备份入口 | 本地文件导出 / 导入、旧剪贴板格式兼容、预览及结果报告 | 文件选择与导出由用户发起；原 CSV 仍仅用于场次表格，不冒充完整备份。 |
| `tests/contracts/`、`e2e/` | 有区别的合成集合及独立键；下载文件→空测试来源恢复→读回；注入失败和重试 | 不访问个人浏览器数据，不以真实手牌充当测试夹具。 |
| 当前版本、架构与验收文档 | 只在功能实现后记录格式与实际行为，补正相关过期描述 | 不在规划阶段预写“迁移完成”或发布状态。 |

最小接口职责为：`readBackup` 解析输入并返回问题；`planRestore` 对比当前快照、列出新增和冲突，全程无写入；`applyRestore` 执行确认后的计划，等待落盘并返回逐项结果。命名可随实现调整，职责必须保留。用户在预览后选择保留本地或采用导入值，计划关联预览时的数据版本；执行前数据变化则重做预览，避免旧计划覆盖新编辑。

特别处理三种容易遗漏的情况：主题键是原始字符串，不能通过统一 JSON 解析静默丢失；损坏的单键应列入报告并保留原始恢复副本，不能用默认空值掩盖；导入恢复的计时先暂停待确认，不能触发补记一串过期日志。当前 `BaseRepo.persistNow()` 已提供可等待结果，应优先复用，不通过立即刷新来“完成”导入。

本批结束的可演示结果是：在隔离测试来源建一套合成记录，下载备份，导入空来源后能查回手牌、收尾、策略、两类 Quiz 的掌握度和错题；重复导入不增加记录，模拟写入失败可重试。只有备份校验、恢复结果与这些用户可见行为通过，才进入 R1。

### 后续界面接线与练习细分

R1 先使旧业务在新导航中可达，随后按批次替换页面内部。候选路由为 `#/home`、`#/play`、`#/review`、`#/study`、`#/practice`、`#/tools`、`#/opponents`；详情使用本地对象 ID。原有 `Navigation.goToHand / goToSession / goToStrategy / goToOpponent` 通过适配层继续工作，避免一次性改写所有来源入口。页面的筛选、滚动和表单草稿由各工作区保留，业务数据仍由原 Repo 管理。

| 批次 | 页面到能力的接线 | 可见结果 |
| --- | --- | --- |
| R1 | 首页任务摘要 → 现有计时 / 场次 / Mark / 学习记录；导航 → 原页面适配 | 用户在新壳能找到全部既有功能，知道下一步。 |
| R2 | 牌局 → `Timer`、`MarksRepo`、情绪与休息；工具 → `Odds` 及速查资料 | 能连续计时、快记和计算，切页不重置任务。 |
| R3 | 复盘 → 导入计划、`SessionClosure`、`HandReplay`、Radar；对手 → 别名与笔记 | 一场的导入、关联、查看与收尾能够接续；返回保留位置。 |
| R4 | 学习 → 主题、概念、策略与来源；练习 → 题型适配、专项和回答历史 | 从具体问题出发完成作答、对比与复练，回到相关手牌或材料。 |

R4 内按下列顺序交付可用切片，每片均进入同一备份与离线机制，不建立孤立训练小应用：

1. **概念题与范围倾向题。** 复用概念题目 ID 和内容；范围题改写问题与反馈。先完成准备、作答、对比、总结、历史与复习，再扩展筛选。避免先制作所有高级设置。
2. **个人手牌盲测。** 先验证决策归属、行动前缀与可见信息；资格不明时人工确认局面或返回普通回放。当前匿名翻后行动不能仅凭回放解析成功就自动进入题池。把未来牌、行动和结果设为反例夹具，检查画面与可访问内容；只记录复盘，不自动判 GTO 对错。
3. **从策略和手牌进入专项。** 保留来源、学习问题、筛选和返回位置；题目缺失可回材料，复练回到冻结的原题条件。来源被删除或修改时，已有最小快照供回看；缺少旧修订的遗留记录明确标注，不用新答案重新评分。

每轮只实现实际可用的输入和难度。范围聚合频率能支持整体分布练习，不能支持某个底牌的混合行动评分；普通历史回放不能支持偏离原行动后的模拟分支。首版采用单节点、单任务、手动下一题，无需以完整对战引擎作为完成前提。
