# Poker product direction

研究日期：2026-10-16。本文回答如何借鉴 GTO Wizard 与开源项目，建设适合个人 Cash 学习、复盘的产品；属于产品建议与后续批次输入，不代表下述能力已经实现。

页面与流程的详细规格仍由[新版蓝图](poker-redesign-blueprint.md)承担，原有实施依赖与恢复要求由[重设计路线图](poker-redesign-roadmap.md)承担；开源项目的技术核查与采用判断见[工具研究](poker-tooling-research.md)。本文不另建一份功能完成清单。

## 推荐目标

让用户能连续完成一次真实任务：记下困惑，找回手牌，停在决策发生前，研究适合该局面的材料，练习同一问题，并在后来的样本中回看自己的理解。

主线是 Cash 9max / 200bb，次线是 Cash 6max / 100bb。目标档案和手牌、资料的实际条件分别保留；没有适配主线的数据时，保留待研究问题，其他条件的资料作为独立参考。

优秀程度先用三个结果判断：任务能否接续，答案是否有据，下一次打开时是否知道该继续什么。视觉、速度、恢复和离线能力都服务于这些结果。

## 产品建设顺序

木下后续已确认翻后是学习重点。恢复、范围工作区和首批受限答案已有独立实施记录；下一阶段按[翻后学习计划](postflop-learning-plan.md)推进，优先贯通具体决策的判断、学习、盲练与回看。下表保留研究时点的依赖分析，不作为下一批开发排序。

以下是已有路线图的优先级建议。已经交付的工作台继续复用；恢复与离线依赖没有因工作台先行就被视为完成。

| 顺序 | 用户能得到什么 | 复用与新增 | 完成时的可演示结果 |
| --- | --- | --- | --- |
| 1. 补齐恢复与使用连续性 | 手里的记录、学习和草稿可以放心保留；牌局结束知道如何收尾。 | 延续 R0–R3，复用 Repo、导入计划、Mark、Session Closure 和现有工作台。 | 合成完整备份可在空环境恢复；完成计时快记→导入→关联→复盘→收尾，并能中断后继续。 |
| 2. 建范围工作区 | 在应用内查询、编辑和比较自己的翻前范围。 | Study 内新增范围视图，复用来源、工作台与恢复入口；先提供手工输入和明确支持的导入格式。 | 保存一份带条件与来源的范围，关闭后找回，导出后可恢复；能看出它是个人范围还是求解结果。 |
| 3. 接通第一批可靠答案 | 同一份数据用于查看、作答和反馈。 | 先验证一个完整场景的数据，再扩展场景数量；复用 Practice 会话、冻结版本和历史。 | 选场景→查看范围→进入练习→提交→按对应答案对照→回到所选节点；数据缺失的手牌不会被判为 Fold。 |
| 4. 做周期回看 | 下次打开能继续问题，知道哪些理解尚需复测。 | 复用专项、学习记录、周复盘、Signal 与策略修订，增加任务编排。 | 从一条周复盘记录找到原手牌、材料、练习与新样本；不同题型和条件的结果分别呈现。 |
| 5. 扩大数据与求解能力 | 能研究更多真实遇到的局面。 | 用独立 solver 工具生成并核验小型数据包，经导入进入同一产品。 | 一个精确局面可重算、可解释差异、可冻结版本；验证通过后才批量生产。 |

这些批次以可用结果拆分，不承诺未经实际测量的工期。范围界面可先使用明确标为演示的合成数据验证交互；演示值不能进入正式答案库、学习统计或发布内容。

## 范围工作区的最小范围

首批集中处理翻前范围的查看、编辑、保存与导入，不要求完整对战引擎。

- 桌面：左侧场景和行动路径，中间矩阵，右侧所选手牌详情；当前问题与返回入口持续可见。
- 手机：先显示局面和矩阵，点手牌再展开详情；高级条件按需展开。动作以文字和频率同时表达，不能只靠颜色。
- 两种数据分别呈现：个人设定的范围可编辑；已收录的求解结果保留原版本，修改后另存个人版本。
- 矩阵中的 169 个格子是起手牌类别。具体花色组合、范围权重和动作概率分别保留；没有组合数据就显示类别层面的结果。
- 范围总占比按组合数和权重计算；有公共牌时排除不可能组合。筛选后明确分母，不能把矩阵格数当组合数。
- 支持的导入语法先写清楚；遇到未知动作、重复手牌、无效权重或缺失条件，给出可定位的问题，确认前不修改本地范围。
- 来源、版本与关键条件随范围导出；练习保存当时使用的答案快照。更新范围后，历史回答仍按原版本回看。

是否复用第三方矩阵组件取决于其输入语义、许可证、移动端和离线成本；技术核查见[工具研究](poker-tooling-research.md)。不为一个矩阵整体更换应用框架。

当前优先参考 [RangeAssistant](https://github.com/HoldemPokerTools/RangeAssistant) 的混合频率编辑、拖拽复制及格式转换。保留本项目的 Vanilla ES modules、Store 和工作台；采用哪些源码片段，待最小兼容实验后确定，并保留相应许可与署名。

## 答案数据先解决什么

在本轮核查范围内，尚未找到已验证可使用、可分发且完整适配 Cash 9max / 200bb 的答案库。这是当前证据状态，不能推导为网上不存在这样的数据。

第一批数据需要同时回答：

1. **对应哪种游戏？** Cash / MTT、桌型、有效筹码、位置、前序行动与尺寸、抽水及上限、ante / straddle；翻后还要有公共牌、底池、剩余筹码、入池范围和动作树。
2. **每个数字表示什么？** 范围权重、节点内动作概率、EV 的单位与计量起点；缺失、不可达与零频率分开。
3. **为什么能用？** 来源、使用与分发依据、生成工具和参数、答案版本；代码许可证与随附策略数据分别核查。
4. **拿来支持哪种功能？** 范围浏览、个人计划练习、整体分布估计、逐手动作对照、EV 评价各自声明能力。

有条件匹配的动作频率即可展示混合策略，但低频动作不等于错误，也不能凭最高频动作宣称唯一最优。只有相同节点、动作集合和单位下的动作 EV 才能支持 EV 差值；EV 差值的展示精度还要考虑求解误差。

可以先验证条件明确的 6max / 100bb 数据，并作为独立内容交付；它不会替代主线 9max / 200bb 的缺口。9max 桌中的一手牌若翻后仅剩两人，可研究对应的双人子局面，但必须匹配之前的行动与入池范围；双人翻后求解器不因此成为九人翻前或多人底池求解器。

## 复用策略

| 能力 | 建设判断 |
| --- | --- |
| 已有 GG 解析、导入去重、持久化、回放、工作台和练习历史 | 优先保留核心。出现明确缺口后局部替换，避免抹掉已验证的牌局语义和兼容行为。 |
| 手牌交换格式与规则引擎 | 参考 PHH / PokerKit 等已有规范和实现；先做离线适配实验，不让主应用运行依赖 Python 服务。 |
| 范围编辑与专项训练 UI | 参考已有开源项目的交互和格式，挑选可独立移植的小部分；附带数据单独验证。 |
| 求解器与数据生产 | 独立运行、冻结输入、导出数据，经校验后导入；先证明一个小局面，避免把计算资源和工具故障带进日常学习。 |
| 支持离线、备份、恢复和更新 | 延续现有路线图，复用工程基础。首次无缓存、缓存完成、断网、升级和恢复分别验收。 |

此前重设计方向允许网页应用为主并取消必须单文件双击的要求，而当前 `AGENTS.md` / `CONTEXT.md` 仍规定单文件及 `file://`。本文不改动构建契约；涉及 R1 的实际工程变更时，应先统一这些记录与已确认方向，再同步建立新的产物和离线验收。

## 用真实任务判断提升

固定以下任务进行旧流程与新流程对照，记录完成与否、找入口次数、重复输入、丢失位置和需人工救回的步骤；以下是验收方法，不是已经测得的提升：

| 任务 | 需要观察的结果 |
| --- | --- |
| 牌局中留下一条疑问，收尾后找到对应手牌 | 不要求当场填长表单；Mark 和手牌关系能找回。 |
| 选一个翻牌决策，研究后回到原节点 | 街道、行动位置、疑问与草稿不丢失；不会被整手最后一街带偏。 |
| 选一个已收录的翻前场景，理解混合策略并练习 | 条件和动作含义清楚；答案源一致，反馈能解释所选动作。 |
| 只做十分钟练习，隔天继续并复练 | 开始设置少，进度可恢复；历史能找到当时的题目与资料。 |
| 导出，再在隔离空环境恢复；断网继续使用 | 数据关系和学习记录可核对；外部材料不可用时核心任务仍可进行。 |
| 一周后查看某个问题的变化 | 能区分阅读、练习表现和新手牌样本；盈利不能替代决策质量。 |

内容扩大前，再看场景覆盖率、缺答案比例和条件不匹配比例。统计时分别展示题型、档案与答案版本；不合成一个缺乏含义的总 GTO 分数。
