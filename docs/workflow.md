# 开发与发布工作流

## 适用范围

这是独立 Poker 助手使用的轻量流程。它借鉴 Catstarry 的证据和关卡纪律，但不引入 Catstarry 的框架、服务或多阶段调度模型。

## 日常开发

确认目标、范围及工作区状态 → 实施最小修改 → 验证受影响的行为 → 说明结果与剩余限制。

| 改动 | 默认验证 |
| --- | --- |
| 纯文档 | 内容、链接和改动差异；不运行应用测试。 |
| 界面文案 | 核对内容与实际显示；按涉及的交互补相关操作验证。 |
| 局部样式或交互 | 查看受影响页面或操作；布局或触控变化时核对相应屏幕宽度。 |
| 共享样式或交互 | 覆盖受影响的代表性入口及相关状态；按布局、触控影响选择屏幕宽度。 |
| 局部逻辑 | 运行对应模块的定向检查；修复 Bug 时复查原症状。 |
| 解析、存储、恢复、评分或求解数据 | 使用代表性输入核对相关逻辑、兼容与失败行为；求解答案接入前核验数值依据。 |
| 构建、入口、公共依赖，或影响多个核心流程的改动 | 运行完整检查，补相关操作验证。 |

以风险最高的受影响行为选择范围，不因新增文件或模块自动扩大到全量测试。一次检查已支持结论后，只有新改动、失败或具体疑点才重跑；先跑定向检查不意味着之后必须再跑完整检查。

每轮沟通不触发版本升级。形成需要区分的功能批次或发布候选时再同步版本；日常修改沿用当前版本。更新相关的现有文档；只有确有复现、交接或审计需要时才单独建立报告，不为每轮工作新增验证文档。

交付先说明实际使用路径、变化及限制。验证用一句话概括覆盖范围和结果，必要时提供失败详情或证据入口；测试数量不作为产品收益。

## 工作区保护

权限和已有修改保护见 `AGENTS.md`。同一连续任务中，已读内容保持有效；文件变化、并行编辑或上下文恢复时重新核对相应状态。未提交工作区可用于开发预览，不能当作已确认的发布基线。

## 检查入口

命令以 `package.json` 的 `scripts` 为准。定向逻辑检查可选择对应的 `tests/contracts/*.test.js`；浏览器检查可选择对应的 `e2e/*.spec.js` 或具体场景。

`npm run check` 会构建临时生产产物，检查单文件契约，运行数据契约测试，并把浏览器冒烟跑在**生产构建的预览服务器**上（`vite preview`，覆盖 CSP 与内联产物的真实行为），不会覆盖受 Git 跟踪的 `dist` 目录。单独运行 `npm run test:e2e` 时仍使用 dev server。

生产预览不复用已有服务，避免验证到旧产物；并行检查遇到端口占用时可通过 `E2E_PREVIEW_PORT` 指定独立端口。

涉及 CSP、内联产物或离线行为时，使用生产构建验证，并按影响补 `file://` 场景；单独运行 dev 模式的 E2E 不覆盖这些条件。

## PR 与发布

确认任务范围与基线 → 实施、验证和审查 → 提交任务分支并创建或更新 PR → 核对合并范围及检查结果 → 合并并跟进部署 → 检查目标 URL。

Agent 负责核对需求与实现、审查最终差异并修复阻塞问题；是否增加独立审查按复杂度和风险决定，不要求每个任务都使用 subagent。检查结果应对应拟合并内容；差异变化后只补受影响的验证，不把旧结果套到未检查的改动上。

应用发布前运行 `npm run check` 并验证相关操作；纯文档 PR 按日常检查尺度处理。需要木下实际使用的体验验收单独标明，只有已明确为发布前置条件时才等待，不把自动检查当作用户验收。

GitHub Pages 工作流在推送 `master` 后运行 `npm run check`，再构建和部署。Netlify 仓库配置只执行构建，发布前的完整检查由 PR 流程完成。合并可能触发生产部署，应在合并前确认本次发布范围；本地检查、浏览器验证、CI、部署和用户验收分别记录。

需要回滚时，使用已记录的已验证提交或产物，并复查目标 URL。

## 部署目标

- Netlify 是主入口候选；平台绑定与历史核查记录见 `docs/deployment-baseline.md`，建立新发布基线时按需复核。
- GitHub Pages 保留为备用入口，并通过 `.github/workflows/static.yml` 使用同一套源码构建。
- `file://` 是离线分发场景，需要与 HTTPS 行为分开验证。

## 发布证据

一次构建或一次合并本身不代表生产发布。应用发布证据可记录在 PR 中，无需另建报告，包括：

- source SHA
- 应用版本
- 产物 hash
- 目标 URL
- 自动检查结果
- 人工验收结果（如需；未完成时明确标注）
- 线上冒烟结果
- 回滚点

Git 与生产操作权限统一见 `AGENTS.md`。
