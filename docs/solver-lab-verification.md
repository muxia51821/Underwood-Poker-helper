## 解析基准及记账

公共牌 `Ks 7d 2c 8h 3d`。OOP 的 KK 剩 3 个组合，A4s／A5s 各 4 个；IP 的 TT／JJ 各 6 个。独立枚举 132 对兼容组合，36 对由 KK 获胜，其余由 IP 获胜，无平局。免抽水、无 ICM，不再发牌。

记初始底池 P=10、下注额 B。OOP 只能过牌／下注，过牌后 IP 强制过牌摊牌，面对下注只能弃牌／跟注。

- IP 范围加权跟注率为 P/(P+B)：A 为 2/3，B 为 1/2。
- 价值牌总下注，诈唬下注质量为 3B/(P+B)：A 为 1 个加权组合，B 为 1.5 个；不要求非唯一解的逐花色频率一致。
- 所有 EV 均以求解起点计账，初始底池的一半记入各方原有投入。A／B 的 OOP 根 EV 为 −15/11、−10/11bb，IP 相反。
- 诈唬牌过牌／下注均约 −5bb；KK 过牌为 +5bb，下注分别约 +8.333333／+10bb；IP 面对下注弃牌／跟注均约 −5bb。

动作 EV 是选择该动作后双方继续采用所求平均策略的价值。主引擎读取子树时 `maximize=false`，没有用最佳回应值冒充动作 EV。对照引擎动作值扣除 P/2，适配范围仅限这三类当前行动者此前尚未投入的节点。NashConv 统一为双方单方改进收益之和，对照引擎原报告值乘以 2，再用独立组合枚举核查。

## 核验范围与环境限制

实际检查包括：解析根／动作 EV、独立策略继续价值、双引擎对照、花色置换、牌面阻断、零兼容判定、频率归一化、动作金额与 EV 单位。零兼容判定由独立辅助测试覆盖；当前两样例的可达组合都有兼容对手，不声称已求解额外零质量局面。产品中的 `null`／不可达处理另有契约检查。

工具为固定 Rust GNU 1.99.1、w64devkit 2.10.1，已校验官方 SHA-256。Rust GNU 写入本机用户 EFS 加密目录出现 Windows error 17，最小编译复现后改用仓库外 `D:/PokerResearch/2026-10-16-solutions`；未修改全局 PATH。使用官方 `rust-mingw` 组件和 `link-self-contained=yes` 完成 CRT 链接。旧对照引擎在新编译器下需要单独允许 `dangerous-implicit-autorefs` 旧式语法 lint；上游源码未修改，数值验收不受此设置替代。

两个原生引擎均关闭默认并行特性、压缩、自动全下及加注，没有购买策略、读取个人牌局或上传数据。此结果证明这两个受限模型可核验，不证明未来转牌、深码翻前库、商业产品数据或任意第三方文件可直接兼容。
