# 首次真实历史导入验收

目标是验证产品的真实使用链，不是用一次大导入得出策略结论。仅在批量导入 P2 已完成审查、通过检查并发布到准备长期使用的同一入口后执行。

## 开始前

1. 在目标入口导出当前本地数据，保存为可恢复备份；原始 `.txt` 保持不动。
2. 只选定一个入口进行首次导入。`file://`、本地开发地址和线上地址是不同的浏览器存储空间，不能把它们当同一份数据的交叉验证。
3. 通过应用手动选择已整理的历史 `.txt`。不自动扫描目录、不上传原始手牌、不处理 zip。

## 一次完成的导入验收

1. 一次选择全部历史文件，确认预览顺序与选择顺序一致；大批量界面应只给概要和有限样本，不逐手生成勾选列表。
2. 在点击确认前记录界面给出的：文件数、识别到的牌局块、有效解析数、失败数及原因、跨文件重复数、将新建/更新的 Session 数。失败不要求为零，但每个失败必须可见，不能静默丢失。
3. 执行“导入全部新手牌”后，等待 IndexedDB 真正落库完成的成功提示；不要以点击后的 toast 或进度动画作为完成依据。
4. 关闭并重新打开同一入口，核对导入后的手牌数、失败/重复记录和 Session 聚合仍在。任选早期、近期、6max、9max 和不同盲注的 6 至 8 手，检查日期、Hero cards、position、BB、tableMax 与所属 Session 是否合理。
5. 从同一入口再导出一次。导出能成功，且手牌总数与重开后的应用一致，即视为最小恢复证据；不需要把牌局内容交给 AI。

## 第一场真实使用链

在一次新的 Session 结束后：导入该场 `.txt`，打开 Session Closure，处理 Mark 与候选手牌，只复盘真正值得看的手，最后确认收尾。这里验证的是“结束后必有一个低阻力收尾动作”，不是强迫每手都写分析。

## 何时停止并回报问题

立刻停止继续导入，保留原始文件和导出备份，并只回传计数/截图（不含手牌内容），如果出现任一情况：

- 重开后手牌数或 Session 总手数减少；
- 已存在 Session 的 hands/profit 没有随本次导入更新；
- 失败牌局没有出现在可见失败清单；
- 大量合理的手牌被标成未知桌型、错误盲注或错误日期；
- 导入完成提示后仍在刷新中丢失数据。

## 验收回传模板

```text
入口：线上 / file:// / 本地
文件数：
牌局块 / 有效解析 / 失败 / 重复：
新建 Session / 更新 Session：
重开后手牌总数：
抽样发现：无 / 简述
Session Closure：完成 / 未完成，原因
```

首次导入只完成“数据事实可用”的阶段门槛。至少完成 3 次 Session Closure 后，再从 Radar 候选中选择 1 至 2 个 Dossier；那时才开始判断哪些个人规律值得用外部 GTO/MDA 证据检验。
